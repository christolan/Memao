## 设置页清晰化方案 · 已实现／已验收

2026-11-08 用户反馈当前设置页的文字说明与可交互按钮难以区分，收到方案后明确表示“不错，完成新方案落地”。本方案已由子 Agent 分工完成 UI、缓存状态与专项测试，主 Agent 完成集成、逐项验收及 0.1.14 手机交付。主题单选、账号导航行、只读存储统计与独立描边操作均已实现；320 dp／2 倍字体自动回流、宽屏 640 dp 内容上限、深浅主题及清理反馈通过检查。缓存状态同步防重复操作，迟到读取不覆盖清理结果；切账号期间的全局清理继续，旧账号成功提示不串出；失败可重试。以下为确认方案与实施标准，完成证据见 [Memao 首版开发准备与接口核对](development-and-acceptance.md)。

### 现状判断

当前外观项为三行文字，仅选中项带勾，未选中项缺乏明显控件外形；清理普通缓存使用无边框的次级 MmButton，文字为 13 sp，与周围说明接近。账号入口已有右箭头，是现有清晰线索，应保留。存储说明较长，普通缓存、保护附件和执行清理之间层级不够明确。

### 推荐布局与视觉规则

延续已确认的黑白灰、留白极简、Lucide 图标及顶部固定标题。按外观、服务器、本机存储、应用信息排列。

- 外观：将原三行选项合并为一个有明确外边界的三段单选控件：跟随系统／浅色／深色。选中项使用高对比实底、反色文字及勾；未选中项仍处于清楚的控件边界内。点击立即生效，保留现有主题保存逻辑。大字体或窄空间无法容纳时改为三行完整单选项，保持可辨识边框与选中标识，不裁字或缩小字体。
- 服务器：保留“管理账号”整行入口，使用轻微灰底、8 dp 小圆角、标题与当前账号摘要，右侧始终显示 chevron-right。整行可点，进入现有服务器账号页；箭头只用于导航入口。
- 本机存储：标题旁说明“所有账号”。占用数据使用无底色、无箭头的只读标签—数值行；数值右对齐。普通缓存和受保护的草稿及附件分成两个信息组，草稿附件旁使用 shield-check 图标强化保护含义，不增加可点击外形。
- 清理：将“清理普通缓存”改为中性描边按钮，eraser 图标＋动词标签，触区至少 48 dp，和统计区留出 20–24 dp。按钮不使用跳转箭头，不用危险红色。保留现有点击执行逻辑，清理中禁用重复点击、显示“正在清理…”，完成后更新真实统计并反馈结果，失败保留原数据并可重试。
- 应用信息：保留 Memao、口号、兼容版本及简体中文信息，作为只读页尾；不添加箭头、底色或伪装成入口。此次不增加版本检查、退出登录等功能。

### 推荐文案

| 位置 | 文案 |
| --- | --- |
| 账号入口 | 管理账号；当前：\{账号显示名\} |
| 普通缓存 | 普通缓存　\{实际占用\} |
| 普通缓存说明 | 按需缓存，默认上限 1 GB。 |
| 草稿附件 | 受保护的草稿及附件　\{实际占用\} |
| 草稿附件说明 | 不参与自动清理，总占用可超过上限。 |
| 操作按钮 | 清理普通缓存 |
| 按钮下说明 | 保留所有未发送草稿及其图片、音频。 |
| 完成反馈 | 已清理普通缓存，草稿及附件完整保留。 |

普通缓存 1 GB 为所有账号合计的既有默认策略；保护附件不计入普通缓存额度。清理只处理普通缓存，不影响未发送草稿正文及其图片、音频。草稿删除继续使用现有草稿页独立操作。无需在设置说明中再放一段无操作入口的“请前往草稿页”。

### 尺寸、反馈与适配

建议页面水平留白 24 dp；分组间距 24 dp，使用细分隔线；顶部标题 16 sp、中等字重，设置项 15–16 sp，操作按钮 14 sp，辅助说明 13 sp／约 21 sp 行高。辅助说明保持足够对比度，不用很浅的灰色表达不可点击。按压时给予轻微灰阶反馈；可操作性同时通过控件外形、位置及状态表达。

宽窗口沿用既有常驻抽屉，设置内容为单列、建议最大宽 640 dp，避免文字和数值跨越整张内屏；窗口变窄自然回流。字体放大后行高增长，数值可换行，不固定高度截断。账号名长时允许摘要换行，箭头保留位置。

按已有授权采用的常规交互默认方案：触区至少 48×48 dp；普通小字对比度至少 4.5:1；主题暴露 RadioButton／selected 语义，入口和执行操作暴露 Button 语义，只读说明不加入点击动作。依据 [Android 无障碍指南](https://developer.android.com/guide/topics/ui/accessibility/apps)，这些是可调整的实施默认值，不记为用户逐项确认。

读取缓存时显示“读取中…”，不把尚未返回的数据写成 0 B；读取失败显示明确错误并提供重试。成功读取且确实无可清理缓存时，按钮禁用并显示“暂无可清理缓存”。真实清理结果以 Repository 返回统计为准，不在产品中写死归零。

### 实施验收条件

- 无需试点即可区分单选项、进入下一页的入口、执行按钮和只读说明；不可点击的占用与应用信息没有箭头或按钮外形。
- 深浅主题、窄窗口、宽窗口、大字体下三种控件均清晰，正文与操作标签可完整阅读，触区不互相覆盖。
- 主题切换、账号入口、缓存读取／执行／成功／失败／零缓存状态反馈完整；清理中不可重复触发。
- 清理前后校验未发送草稿正文及附件仍在；账号隔离和现有清理范围不变。
- 会话预览仅为本地交互示意，账号名与 128.6 MB／24.8 MB 为设计样本，清理动作只改变示意数据；不是手机运行截图或真实数据验收。手机体验和折叠适配仍需实施后验证。

## 关键流程与文案

### 连接、切换与删除账号

初次使用填写服务器地址和 Token，验证后识别服务端用户，建立服务器＋账号组；不使用账号密码。协议保留用户选择的 HTTP 或 HTTPS。格式校验不会代替服务器连通性、版本和权限校验；后者的真实实现与错误分类待接口核对。

切换账号保留原账号缓存与草稿，并显示目标组内容。Token 失效允许进入该账号已有缓存和草稿，发送前要求更新令牌。按授权补充：更新令牌时必须核对所属用户与当前组一致；若令牌属于另一个用户，提示作为新账号添加，不把两组本地数据合并。

删除二次确认示例：“将清理该账号在这台设备上的本地数据，包括登录令牌和缓存、未发送草稿及草稿中的图片和音频附件；不影响服务端账号、笔记及其他账号的数据。”弹窗带账号名称、服务器地址与草稿数量，按钮为取消／删除账号。取消不执行清理；删除最后一个本地账号后回到连接页。

### 草稿、普通缓存与返回

2026-11-17 用户确认草稿状态设计，见 [R79](planning.md#r79-草稿本地保存状态)及[可点击设计稿](assets/design/memao-draft-search-review.html)。底部及时反馈待写入、写入成功和失败，失败提供就地「重试保存」。顶栏保留「保存」按钮，用户要求去掉「保存到服务器」提示。

2026-11-08 R70：用户明确要求未修改退出不保存草稿。正文和附件不变时，不因光标、选区、预览或后台返回生成新增草稿；原有草稿保留，本次创建副本在正常退出时若与进入基线相同则清理，已有发送尝试的内容不自动删除。此规则同步覆盖返回、切页及切账号，实际改动仍自动保存且不自动发送。

2026-11-08 已确认 R68：草稿、归档和笔记各自拥有独立 Compose 页面与 ViewModel；切页保留各自列表及滚动位置，不因切回而发起服务器刷新。草稿实时观察本地保存／删除；归档首次进入加载，后续由下拉或相关操作同步更新。该调整保留自动保存、账号隔离与现有详情／编辑返回规则。0.1.11（12）已实现并通过六项专项及相关回归，已保留数据覆盖安装手机；实施及验收见 [Memao 首版开发准备与接口核对](development-and-acceptance.md)。

草稿详情说明“已保存在本机”，继续编辑沿用既定源码与预览设计，不将自动保存等同于发送。删除草稿单独确认，明确正文、图片和音频的本地清理范围，以及服务端原笔记不变；草稿附件共用资源保护按 R28—R31 和 D01—D03 执行。

设置中的清理按钮只清普通缓存，不删除草稿及其依赖附件。用户已确认按需缓存、不自动预下载全部历史内容、所有账号普通缓存合计默认 1 GB，优先回收较久未用内容；草稿依赖文件受保护、额度外保留。预览显示的占用仍为设计样本，不代表已实现缓存策略。草稿与归档不新增批量操作。

### 失败、结果未知与冲突

附件上传失败保留完整草稿，允许用户手动重试；请求超时后，如无法确定笔记是否已创建，先核对服务端结果，不能把重复创建当作通用重试方式。实际去重、版本比较与原子提交能力须核对 Memos 0.31.0，预览不作技术保证。

冲突不预选处理方式。服务端和草稿依次展示更新时间、正文及附件差异；可保留服务端版本、用草稿覆盖、另存为新的私密笔记。按授权确定的防丢失默认方案：选择保留服务端版本时不自动删除本地修改草稿，用户可随后单独删除；取消或稍后处理同样保留草稿。覆盖和另存只有在用户明确选择并继续后才执行，执行前仍需核对版本变化；执行失败继续保留草稿。

本地保存失败保持编辑现场，明确显示失败及重试，不显示“已保存”或静默退出。令牌失效保留当前账号的缓存和草稿，要求更新凭据，不能把草稿发往其他账号。
