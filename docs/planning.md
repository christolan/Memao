## 0.1.17 登录输入框光标居中

2026-11-09 按用户反馈，0.1.16 在 Find N6 上可以启动，但连接页“服务器地址”和 Token 两个输入框的光标偏上。这是视觉修正，不扩展首版功能。处理是让共用输入组件 `MmField` 把光标、文字和占位文字在框内上下居中。版本 0.1.17（versionCode 18）用于覆盖安装 0.1.16。Android 16 模拟器已复现偏移并验证居中；Find N6 / ColorOS 实机仍待用户确认。详情见 [I31](development-issues.md#i31-登录输入框光标偏上)。

## 0.1.16 启动崩溃修复

2026-11-09 按用户反馈，官方优化签名包 0.1.15（versionCode 16）在 Find N6 上打开即退出；关闭优化的诊断包（约 31 MB，对比正式优化包约 8.6 MB）可以启动。用户随后安装官方 Actions 侧载 APK，反馈崩溃“又回来了”。原因是 R8（AGP 9.1 起默认开启）把 `kotlin.text.StringsKt__StringNumberConversionsJVMKt` 重打包为未命名包中的 `z52`，而其包内可见父类仍为 `kotlin.text.k`，系统在 `androidx.startup.InitializationProvider.onCreate` 抛出 `IllegalAccessError`。正式包保留优化和代码收缩，只用 `-dontrepackage` 停止跨包重打包，重建后约 8.2 MB。版本升至 0.1.16（versionCode 17），以便用同一官方签名覆盖安装 0.1.15。改动已合并：[Fix optimized release crash on launch](https://github.com/christolan/Memao/pull/3)，提交 [34b66ad89ec7d22e1de2faf92286608a58f4eb21](https://github.com/christolan/Memao/commit/34b66ad89ec7d22e1de2faf92286608a58f4eb21)，约 10:16（Asia/Shanghai）。Android 16（API 36）ATD 模拟器已复现崩溃，并验证 0.1.16 可冷启动进入登录页（“连接你的 Memos”）；debug 单元测试 47 项运行、0 失败、7 项跳过（需要隔离 Memos 服务器）。用户随后报告 0.1.16 可在 Find N6／ColorOS 上启动，见 [I31](development-issues.md#i31-登录输入框光标偏上)。合并后新的侧载构建见 [Actions run 42550061724](https://github.com/christolan/Memao/actions/runs/42550061724)（截至约 10:17 Asia/Shanghai 仍在进行）；成功后下载应为 [sideload-latest](https://github.com/christolan/Memao/releases/tag/sideload-latest) 的 `Memao-0.1.16-release.apk`。详情见 [I30](development-issues.md#i30-官方优化包启动即退出)。

按用户授权确定的实现细则：笔记与归档各自在本次账号会话首次进入时加载，之后切回恢复已加载列表、分页和滚动位置；手动下拉刷新、关键词／标签变更仍可请求服务端。草稿持续观察本地数据库。归档、恢复、删除、发送和草稿保存通过共享 Repository 更新相关列表，页面状态、请求与错误反馈相互隔离。账号切换清理当前页面会话并按账号恢复持久状态，防止串号；APP 新启动仍默认笔记列表且不自动打开详情。具体实现不要求所有界面对象永久驻留内存。

### R69 列表折叠阅读与长按编辑

2026-11-08 用户明确要求：笔记正文默认最多展示 6 行，超过 6 行折叠；点击正文切换折叠／展开，长按笔记直接编辑；移除服务器笔记详情页，在列表展开即可阅读全文。此项取代 R36 的默认全文规则，以及原 R32—R34 中服务器笔记详情栏的设计。

按用户授权确定的默认方案：6 行按当前宽度、字号和 Markdown 渲染后的实际文字行累计；笔记与归档一致，短笔记保持完整显示。展开状态在当前账号页面会话中按笔记保留，切页或窗口变化不重置；新启动默认折叠。图片、音频仍位于正文下方并保留原交互。复制、编辑、归档／恢复、删除迁入每条笔记的更多菜单，删除仍二次确认。为保障长按编辑，列表正文不触发文字选取，全文复制由菜单提供。宽屏无编辑任务时列表占满可用内容区，编辑时保留原双栏；草稿预览不受此次服务器笔记详情移除影响。发送完成与保留服务端版本返回列表，准备编辑仍遵守附件完整缓存及账号隔离规则。

实施与验收结果：列表渲染／手势、详情移除／编辑准备链路已由子 Agent 分工实现，主 Agent 审查与验收完成。6 行边界、自动换行、Markdown 跨块、长按、管理菜单、切页／窄宽与后台保留状态、迟到请求取消及链接手势均已验证；累计 79 项不同检查通过。0.1.12 已保留数据覆盖安装手机并核验版本和启动；实际设备连续手势与实体折叠仍待试用。证据详见开发准备，开发问题见 I26。

### R70 未修改退出不新增草稿

2026-11-08 用户明确要求：进入编辑状态后，没有任何修改，退出时不要保存草稿。

按授权确定：以正文和附件的实际内容／身份／顺序判断修改，光标、选区、滚动、预览不算修改；本次创建的编辑副本在退出时若与进入基线一致，不留新增草稿，改后还原也按无最终修改处理。已存在的草稿保留，既有附件和未发送内容不自动删除。取消准备、返回、切页和切账号使用同一保护规则；本次已经尝试发送的草稿不自动清理，以保护失败、冲突和结果未知状态。后台仍处在编辑现场时保留保护性保存。仅为空白无附件的新建内容继续不生成草稿。

实施与验收结果：已区分本次新建副本与既有草稿，在保存锁和 Repository 原子校验下清理符合条件的副本，保护取消准备、并发输入与发送。8 项持久化专项及相关回归、JVM 合计 72 项不同检查通过。0.1.13（14）已保留数据覆盖安装手机并核验版本和冷启动；验收明细与强杀／进程回收边界见开发准备，开发问题见 I27。

## 产品定位与使用场景

已确认首版核心使用场景的优先级：

1. 碎片记录：最主要的用途。
2. 图片记录：次要但重要的用途。
3. 历史回顾：通过搜索和标签查找以前的内容。

首版聚焦碎片记录、图片与音频，以及搜索和标签回顾；已明确不针对长文做专项优化。用户已确认优先自用，先做好 OPPO Find N6 体验；公开发布与其他用户支持后置，其他未决边界继续明确。

建议围绕这些场景打通“连接服务器 → 浏览记录 → 快速写下想法或图片 → 手动发送 → 搜索和标签回顾”的完整路径。

以下为候选场景细节，尚未全部确认。后续按碎片记录、图片记录、搜索和标签回顾的顺序细化功能与页面。

- 随手记录一句话，打开编辑器后即可输入，发送结果明确。
- 记录简短内容，按需使用已确认的常用 Markdown、标签和图片。
- 按时间浏览旧笔记，通过关键词或标签找到内容。
- 网络中断时查看已缓存内容，继续保留草稿，联网后主动发送。
- 在网页端修改过笔记后回到 APP，能够识别刷新结果，避免旧内容覆盖新内容。

建议首版以记录、阅读、检索的质量为重点。AI、复杂统计、地图、社区互动等功能先进入候选清单，是否纳入由实际使用需求决定。

### 内容格式兼容约束

已确认常用 Markdown 范围为标题、粗体、斜体、列表、引用、链接和待办清单；首版不提供代码块和表格的编辑能力。客户端可提供的格式必须属于目标 Memos 服务端支持范围，保存后能在服务端正确显示，不采用只有客户端能解析的自定义标记或私有富文本保存格式。

开发准备阶段以 Memos 0.31.0 为目标逐项建立格式对应表；后续开发验证“客户端输入与预览 → 保存到服务端 → 网页端显示 → 再次编辑”的完整路径。此处为已确认的兼容要求，尚未完成各项语法的服务端验证。

编辑方式已确认为 Markdown 源码输入加预览，并提供常用格式快捷按钮；快捷按钮仅生成已确认范围内、可被服务端正确显示的 Markdown，不引入客户端私有格式。

快捷按钮布局与预览切换沿用已认可设计和 D04。服务端已有高级内容完整保留源码；可正常渲染的显示，其余以源码或简化形式安全呈现，不要求网页完全一致，不自动删除或转换。新增图片仍放正文下方，不为既有内容无损保留而扩展插图编辑功能。

## 缓存和草稿的行为细则

已确认：离线可浏览缓存、新建和编辑草稿，也可修改已缓存笔记并先保存为草稿，联网后手动发送，不自动发布。新建草稿与已有笔记修改草稿需要区分，后者保留与原服务器笔记的对应关系，正常发送时用于更新原笔记；冲突时可按用户选择另存为新笔记。

草稿完整保留文字、图片和音频，包括离线新添加的附件；关闭或重启 APP 后可恢复，联网后仍由用户手动发送。正文与附件须以可持久恢复的方式保存，不能只依赖临时附件访问状态。

发送已有笔记的修改草稿前，如发现服务端笔记已变化，提示冲突并由用户选择：保留服务端版本（不写入覆盖）；用草稿覆盖原笔记；另存为新的私密笔记并保留服务端原笔记。选择前不执行覆盖或另存，取消选择时保留草稿。冲突检测与提交期间发生再次修改的处理能力在接口核对阶段确认。

清理普通缓存时始终保留未发送草稿正文及其图片、音频附件，删除草稿需要单独操作。缓存与草稿共用的附件资源，只要仍被草稿依赖就须保留；清理后草稿仍可恢复并在联网后手动发送。

支持保存并切换多组服务器账号；各组登录状态、凭据、缓存与草稿须独立，切换后不混合显示内容，也不能跨组发送草稿。下列常规细则已按用户授权确定，具体交互统一见本节 D01—D08；涉及接口能力的部分仍需核对。

- 首次使用必须连接并登录服务器；缓存不形成独立账号或独立笔记库。
- 断网展示已缓存内容，并说明内容可能不是服务器最新状态；未缓存的图片和笔记不能伪装为已加载。
- 草稿与服务器、账号绑定，界面区分“已保存在设备”和“已发送到服务器”。
- 网络恢复后提示用户有未发送草稿，由用户主动发送。
- 发送失败保留输入和附件状态。请求超时而结果未知时，先核对服务器结果，避免盲目重试产生重复笔记。
- 冲突提示需要让用户能判断服务端版本与草稿的区别；版本比较、附件处理及确认交互按后续接口核对和 UI 设计细化。
- 已确认账号保存在列表中，切换保留数据。从列表删除账号前必须二次确认，并明确提示会清理该账号本地数据，包括未发送草稿及其图片、音频附件，不影响服务端数据。确认后清理该组 Token、登录状态、缓存、草稿与附件；取消则不删除账号和数据，也不影响其他账号组。
- 不在文档和日志中记录真实密码或 Token；凭据使用 Android 提供的安全机制保存。

已确认普通缓存按需保存，不自动下载全账号历史内容；所有账号合计默认 1 GB，达到上限优先回收较久未使用的普通缓存。未发送草稿及其依赖附件不纳入可自动清理额度，实际总占用可超过上限。在线准备编辑时补齐全部附件，回收或文件缺失后重新判定完整性。具体回收与文件引用机制属工程细化。冲突按 P01 已确认的提交前检查及并发窗口执行，草稿恢复、删除入口及常规错误反馈按下方方案执行。

### 按用户授权确定的常规交互默认方案

以下方案由助手依据用户授权确定，并非用户逐项选择；可在设计评审时调整。平台资料用于状态恢复、窗口适配与可访问性依据，具体产品取舍结合 Memao 已确认需求确定。

- D01 草稿保存与退出：正文或附件实际变化持续保存到本地，退出编辑、切换页面或账号、在右栏打开其他笔记前完成保存。有未提交改动自动保留草稿，不弹常规确认；按 R70，进入编辑未改动直接退出不新增草稿，原有草稿保留。光标／选区、滚动和预览不算内容修改；仅完全空白且无附件的新建编辑器不生成草稿。显示真实保存状态，未改动显示“未修改”；本地保存失败保留编辑现场并提供重试，不静默退出。自动保存不会发送到服务器。
- D02 草稿入口与删除：草稿页仅显示当前服务器账号的草稿，按最近编辑时间倒序，区分新建草稿与修改草稿；点击继续编辑。再次编辑同一笔记时恢复其现有修改草稿，避免重复分叉。删除草稿是独立操作，确认中明确会删除正文及草稿附件，不影响服务端原笔记；成功发送后清理已提交草稿，不删除仍被其他草稿依赖的附件。发送期间的新修改不得随旧版本提交结果一并清除。按授权补充防丢失默认方案：冲突时选择保留服务端版本，不自动删除本地修改草稿，删除仍需单独操作。
- D03 手动发送与反馈：编辑器提供明确的“发送”操作；正文为空但含图片或音频时允许发送；完全无内容时不可发送。发送过程中显示进度并防止重复点击；失败保留草稿与附件，说明失败步骤并提供手动重试。结果未知时先核对服务端状态，不盲目重复创建；具体去重能力在 Memos 0.31.0 接口核对中确认。
- D04 返回与键盘：系统返回遵循当前层级，键盘展开时先收起键盘，下一次返回退出当前编辑或详情；页面返回按钮退出当前页面并按 D01 保存草稿。预览切换保留源码、光标及滚动位置，预览时收起键盘，回到编辑时恢复输入位置。附件选择取消不改变已输入内容，系统文件选择器负责选择音频，图片沿用已确认的相册与粘贴方式。
- **D05 列表、搜索与刷新**。分别展示首次加载、加载更多、刷新、无内容、搜索无结果和网络错误。刷新失败时保留已显示内容并提供重试。按 R75 提交关键词后检索，清除关键词回到最近搜索。新的关键词从第一页检索，取消返回原笔记列表时恢复筛选和滚动位置。离线检索只覆盖已缓存范围，页面明确提示。
- D06 折叠屏与窗口变化：浏览笔记时列表占满可用内容区；编辑或草稿预览时按当前空间使用约 1:2 双栏，不足回单列。字体放大、分屏和折叠重排保留当前展开状态、搜索、列表位置及编辑任务，键盘不遮挡输入和发送。新启动默认折叠列表；后台切回保留现场。已取消、切页或换账号后，迟到的准备请求不得打开编辑。
- D07 断网、认证与危险操作：用页面内状态说明离线、缓存和未发送草稿，恢复联网不自动发布；Token 失效时在原账号组提示重新连接，保留其草稿和缓存。更新 Token 须核对所属用户与该账号组一致；属于其他用户时作为新账号添加，不混用本地数据。服务端笔记删除与本地草稿删除均使用明确的确认文案；归档及取消归档提供轻量结果反馈，失败保留原状态。账号删除始终沿用用户已确认的二次确认及本地清理边界；需服务器写入的操作离线时不伪装成功。
- D08 可访问性与通用状态：可点击区域以至少 48dp 为基准，图标有清晰语义标签，状态和错误同时用文字表达；支持系统字体缩放和屏幕阅读器。输入错误贴近相关字段显示，保留用户输入；加载中、空状态、失败重试的动作明确。视觉继续采用留白极简，不因采用平台交互惯例改变为 Material Design 风格。

依据：[Android 状态保存](https://developer.android.com/topic/libraries/architecture/saving-states)、[Android 列表与详情适配](https://developer.android.com/develop/ui/compose/layouts/adaptive/list-detail)、[Android 可访问性默认行为](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)。

这些规则不决定其他附件范围、服务器版本兼容或发布方式；相关功能边界继续按已确认与待定记录推进。后台／锁屏音频播放已明确不纳入首版，按 R49 执行。

## 首版验收标准草案

- R75：笔记页右上角进入独立搜索页，空输入显示当前账号最近搜索，键盘和页面按钮可提交，触碰历史可重搜。检查标签交集、无结果、分页、下拉刷新、离线缓存范围、取消返回后的列表现场和历史持久化。搜索中切换账号或取消时，旧请求不能覆盖其他页面或账号的状态。
- R70：从笔记进入编辑未改动退出后持久草稿数量不增加；移动光标、改变选区、切预览和后台返回仍不算正文修改。正文或附件变更自动保存，退出可恢复；改后还原不留本次新增副本，已有草稿的正文、附件身份与时间不因未改动退出而丢失。返回、切页、切账号及取消准备均不遗留未改动副本；尝试发送后的失败／冲突／未知结果继续保留，附件受保护。
- R68：笔记、草稿、归档各有独立 Compose 页面和 ViewModel。先加载并滚动各列表，再反复切换，列表内容、已加载分页与滚动位置均保留，网关列表请求计数不因切回增加。首次进入未加载页面可加载一次；下拉、筛选、加载更多仍有效。慢请求跨页完成不覆盖其他页面状态；账号切换不混用列表。草稿保存／删除、归档／恢复／删除／发送能更新相关列表；窄宽布局和编辑自动保存保持。
- 笔记／归档右上角无刷新按钮；列表到顶下拉能重新请求当前筛选。空列表、短列表和无搜索结果可刷新；普通滚动不误触发，刷新期间不重复请求，完成或失败后进度结束；加载更多不显示下拉刷新进度；草稿不发起服务器刷新。保留筛选、固定标题、离线缓存与重试行为。
- 吸顶标题随当前页面切换，内容滚动不带走标题；顶部不显示 APP 名称，页面内容不重复页面标题。覆盖笔记、草稿、归档、设置、账号、详情及编辑，保留菜单、返回和页面操作；窄宽布局切换保持当前任务。

以下为已确认范围对应的计划验收标准，具体执行证据在实现和联调阶段记录。

- 普通缓存只按需保存，不自动预下载全账号内容；所有账号合计默认 1 GB，优先回收较久未用内容；草稿及依赖附件不受自动回收影响，总占用可超过上限。
- 本人已有公开／受保护个人笔记正常显示和编辑，详情明确可见性，修改不改变原值；已有高级 Markdown 源码无损保留、安全简化显示，不要求网页完全一致。
- 支持选择和复制正文，没有专门的分享入口；APP 名称为 Memao，界面仅简体中文，笔记内容语言不受限制。
- 能使用 HTTP 或 HTTPS 服务器地址与有效 Token 连接目标 Memos 0.31.0 实例并识别账号；两种协议均需覆盖登录与首版笔记操作，不提供账号密码登录。错误地址、无效或失效 Token 及版本问题有清楚提示，真实 Token 不出现在项目文档或日志中。
- 列表、搜索与标签筛选结果只包含当前登录账号本人的个人笔记，不展示其他用户或空间笔记；不提供其他用户内容和 Spaces 入口，新建流程不提供空间选择。
- 首版约定的笔记内容在 APP 与网页端之间读取和修改正确，分页不会漏掉或重复展示条目。
- 常用 Markdown 的标题、粗体、斜体、列表、引用、链接和待办清单保存后均能在目标服务端正确显示；客户端不生成服务端无法识别的格式，首版编辑器不提供代码块和表格功能。
- 能以 Markdown 源码输入和修改内容，并预览显示效果；常用格式快捷按钮生成服务端兼容的 Markdown，不提供所见即所得编辑模式。按钮与预览交互按后续确认的设计验收。
- 页面右上角不再显示「记录」；抽屉内的「记录」入口仍可正常新建。双栏在右栏编辑，单列进入编辑器；新建后自动聚焦正文并弹出键盘。附件来源、退出自动存草稿和已有未发送内容的保护规则保持。
- 新建或编辑的发送结果明确；失败不丢草稿；网络恢复不会自动发布。
- 退出编辑器或切换页面、账号及大屏右栏内容前自动保存未发送内容和修改草稿，不弹常规保存确认；完全空白且无附件的新建编辑器不生成草稿。本地保存失败时保留现场并提供重试，不显示已保存或静默退出。
- 按 D01—D08 检查草稿恢复与删除、发送防重复与失败反馈、返回和预览状态保留、列表与离线搜索状态、窗口适配、认证失效和可访问性；这些默认方案可在设计评审中调整，涉及服务端能力的检查在接口核对后细化。
- 离线新建或修改含图片、音频的草稿后，关闭并重启 APP，正文与附件仍完整、可恢复；联网后可手动发送至原服务器账号，不能因重启丢失附件或自动发布。
- 断网时能读取已缓存范围内的内容；未缓存内容和离线搜索范围有明确提示。
- 已有笔记的正文及全部附件均有可读的本地副本后，才允许离线编辑；只缓存正文或部分附件时可浏览，编辑入口禁用并解释原因。缓存清理或文件丢失后重新判定完整性，不能保留错误的可编辑标记；已有草稿依赖的文件继续受保护。
- 断网时能新建、编辑草稿，并修改已缓存笔记后保存为草稿；恢复网络不会自动发送。正常发送时，新建草稿创建笔记，修改草稿更新对应原笔记；只有用户明确选择另存时才创建新笔记。
- 网页端在离线修改期间更新同一笔记后，发送修改草稿须提示冲突；保留服务端版本不改写原笔记，草稿覆盖更新原笔记，另存创建新的私密笔记并保留原笔记。未选择或取消时不覆盖、不另存且保留草稿；版本比较与提交竞态细节在后续核对。
- 能通过相册选择多张图片，也能粘贴剪贴板图片；首版不提供直接拍照入口。
- 相册选取后上传源文件字节，客户端不改变分辨率或进行有损压缩、自动格式转换；草稿保留原文件，显示缩略图不改变上传源。超出服务端限制时提示并保留草稿，不自动压缩后重试；仅有位图的粘贴源按无损编码保存，不宣称与不存在的原文件字节一致。服务端自身的处理单独验证。
- 选择一张或多张图片后，不填写文字也能手动发布；不能因文字为空拦截纯图片笔记。上传与草稿验收细则在确认后补充。
- APP 新建图文笔记时，图片统一放在文字下方；编辑器不提供正文中间插图的入口。列表中的单张图片按原比例展示，多张采用整齐网格，点击可查看完整图片；具体网格列数、尺寸和间距在设计预览中细化，附件排序交互继续确认。
- 点击笔记图片后进入全屏查看，可用双指缩放，并左右滑动浏览同一笔记的其他图片。
- 新建的纯文字、图文、纯图片及包含音频的笔记在服务端实际保存为私密；新建界面不提供可见性选择。普通内容编辑不自动改变已有笔记的可见性。
- 可选择已有音频文件作为笔记附件添加；首版不提供录音入口或录音功能。
- 新增附件入口只接受图片和音频，不提供视频、PDF、普通文件导入。对服务端已存在的其他附件，普通编辑、草稿恢复和完整集合提交均保留，不因类型未支持而漏传删除。
- 首版实例联调与验收仅保证 Memos 0.31.0；版本不同须明确提示支持范围，不宣称已兼容其他版本。
- 在 OPPO Find N6／Android 16 上，使用根路径服务器及 Memos Token 完成核心流程；不要求子路径、Basic Auth 或其他访问网关适配。HTTP 与 HTTPS 的已确认范围保持，不把普通网络或 TLS 错误误报为需要额外网关登录。
- 只添加音频、不填写文字时也能手动发布私密笔记，不能因文字为空拦截纯音频发布；保存结果与服务端保持兼容。
- 可在 APP 内直接播放笔记音频，并能暂停和拖动进度；暂停后能继续播放，拖动后从所选进度播放。支持格式、上传、缓存与草稿的具体验收细则在确认后补充，转写不视为已纳入。
- 音频播放期间应用进入后台或设备锁屏时暂停，不继续发声；回到前台后保留进度，须用户点击才继续。切换服务器账号停止原账号音频，不把原账号播放状态带到新账号；单纯折叠重排或仍可见的分屏不自动视为离开前台。
- 图片及后续确认的音频操作结果与服务端实际保存结果一致；编辑个人笔记时保留不应改变的属性。首版不操作空间笔记或空间设置。
- 编辑、删除、归档及取消归档操作与服务器状态一致；删除提示和后果清楚。
- 归档后笔记从主列表收起，在独立归档列表中可打开详情；取消归档后恢复主列表，不丢失正文、图片或音频。主列表搜索及标签筛选默认不返回归档笔记，取消归档后可按条件查找；归档页首版不提供独立搜索和标签筛选。
- 选中标签只显示在笔记页面固定标题后，侧边栏标题保持不变；搜索框下无重复标签提示，列表（含归档）和详情底部无独立标签行。清除标签恢复普通标题；正文中的 #标签及数据保留，窄宽屏、长标签与大字体仍可操作。
- 标签筛选位于侧边抽屉，笔记页不再显示横向标签筛选栏；窄屏选择后收起，宽屏常驻。筛选时一次只选择一个标签；选定标签后搜索关键词，结果同时满足标签与关键词条件；清除标签保留关键词。整段输入按正文子串匹配，不区分英文大小写，不按空格拆词，也不解释为正则或通配符；无高级搜索语法，离线只查缓存。
- 在编辑笔记时可以添加或移除该笔记的标签，保存后与服务端一致；不提供独立标签管理页、统一重命名和跨笔记批量移除功能。
- 搜索和标签操作符合约定；首版不提供置顶操作。
- R69：窄宽屏正文均按实际布局最多展示 6 行；恰好 6 行不折叠，超过时折叠，点击完整展开再点收起；长按直接进入编辑，不经过详情。验证跨段落、标题／列表／待办／引用、自动换行、大字体、链接及纯附件笔记；媒体交互和菜单复制／归档／恢复／删除保持。切页、窗口重排及编辑返回保留状态；发送和冲突处理后不进入详情；取消准备或换账号后迟到请求不得打开编辑。
- 外屏与展开内屏的笔记列表默认按创建时间倒序；编辑旧笔记后，其位置仍由创建时间决定。
- 默认跟随系统的浅色或深色外观；设置中可切换为跟随系统、浅色或深色。手动选择按用户设置显示，切换主题不丢失当前笔记、未发送草稿及输入状态；两种外观均按确认后的配色与对比度验收。
- 页面沿用留白极简；全部窗口无底部 dock。窄窗口抽屉默认隐藏，菜单可打开，点遮罩、系统返回或选择目的地后关闭；宽窗口抽屉常驻。四个入口可达且选中状态正确。折叠／分屏跨越门槛时保留当前内容、搜索、草稿、选区与位置；字体放大、深浅色和键盘下仍可用。内容区足够时列表与详情约 1:2，否则单列，不以单列回退关闭常驻抽屉。
- 可保存并切换多组“服务器地址＋账号”，覆盖同一服务器的不同账号以及不同服务器的账号；有效登录可恢复使用，过期登录的处理按后续确认流程验收。
- 切换后列表、搜索、标签、缓存、附件与草稿仅属于当前服务器账号组；原账号尚未完成的请求不能把结果显示或保存到新账号组，草稿不能误发到其他组。
- 清理缓存后，未发送草稿正文、图片与音频附件均保留；即使附件同时被普通缓存引用，也不能删除草稿依赖的资源。重启后仍可恢复并手动发送，删除草稿必须通过独立操作。
- 账号保存在列表中，切换后再切回仍保留该账号数据。删除账号前须显示二次确认，明示将清理该组本地数据，包括未发送草稿及图片、音频附件，且服务端数据不受影响。
- 确认删除后清理该组本地 Token、登录状态、缓存、草稿及附件，不影响其他组或服务端账号与笔记；取消或关闭弹窗则保留账号与全部本地数据。普通缓存清理与删除账号的行为须清楚区分。
- 启动或重启 APP 时即使有历史笔记或旧导航／编辑状态，仍显示默认折叠的笔记列表，不自动进入编辑；宽屏不留空详情栏。未发送草稿及附件保留、可手动继续，后台切回保留列表展开状态或编辑现场。
- 阅读列表笔记或编辑草稿时，折叠与展开保持笔记展开状态、正文与附件、光标及列表位置，不自动发送；编辑中布局切换不得返回列表或按启动规则重置任务。
- 草稿、缓存和账号边界明确，不因切换或删除导致误发与其他账号数据混淆。

性能指标在明确设备与笔记规模后补充，包括启动到可阅读的时间、列表滚动、图片加载、搜索和发送反馈，不在缺乏目标环境时承诺具体数字。
