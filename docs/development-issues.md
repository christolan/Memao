## I42 笔记配图验收的同名节点

2026-11-16 模拟器专项中，双栏编辑页和左侧列表各有一张同名图片。全屏查看时，底层列表缩略图和查看器也共用文件名。按文件名全局查找无法定位唯一节点。测试分别限定列表范围及查看器图片的手势目标，两项均通过复验。

## I41 仅出现在搜索结果中的笔记图片无法加载

2026-11-16 检查共用笔记卡片时发现，附件加载只在普通笔记与归档列表中查找附件所属的笔记。搜索结果命中尚未加载到普通列表的笔记时，点击占位重试也无法找到附件。附件查找已纳入独立搜索结果，沿用原有按账号隔离的下载及缓存流程。Android 17 模拟器已验证四图加载、点选和全屏滑动。

## I40 固定新建入口后的列表测试定位

2026-11-15 固定「记录」按钮后，列表可滚动区域缩短。原测试假定某条笔记会在筛选后的首屏挂载，首轮模拟器验收时找不到该节点。回归改为先滚动到指定笔记，再检查正文和「记录」在进一步滚动前后的坐标。Android 17 模拟器复验通过。

## I39 笔记条目的内容与操作层级

2026-11-15 用户复核 0.1.22 后要求重新出设计稿，并确认将创建时间移到底栏，和展开／收起及更多菜单同行对齐。底栏文字统一字号、颜色和行高，使用箭头标明展开状态，底栏到正文和分割线分别留 12 dp。新版排版随 0.1.23 发布。

首轮模拟器专项中，「展开全文」的单行文本返回溢出标记。截图中四个字完整，实际排版尺寸为 60 × 27 px。测试改为直接核对可见末字符和省略状态，单栏与双栏专项复验通过。

0.1.24 按用户反馈将创建时间和展开／收起调为 14 sp，降低底栏灰色对比度。27 sp 行高和 12 dp 间距用于保持原设计的垂直对齐。 2026-11-15 用户要求再缩小一点，调至 13 sp。

## I38 笔记页顶部空白与条目间距

2026-11-15 用户反馈笔记页顶部空白明显，并要求展开／收起跟正文保持相同行距、条目上下留白对称。旧列表头移除后，列表和加载占位仍各自保留 16 dp 顶部内边距，48 dp 高的时间和菜单行居中后又增加一段视觉空白。移除笔记列表和加载占位的额外顶部内边距，时间和菜单行按内容排版，菜单沿用 48 dp 最小触摸高度。

共用笔记行上下统一为 8 dp。展开／收起从独立的小字号样式和上下内边距改为复用普通正文的排版，保留首尾行高以对齐实际基线。Markdown 段落、标题、引用等仍按各自的规则排版。

## I31 登录输入框光标偏上

2026-11-09 用户在 Find N6（Android 16 / ColorOS）安装 0.1.16 并成功启动后反馈：首次打开的连接页（“连接你的 Memos”）里，服务器地址和 Token 两个输入框在输入时光标没有在框内上下居中。

原因：两个框都用 `MmField`。字体是 `bodyLarge`（16sp，行高 30sp），装饰层 `Box` 默认顶对齐。Android 16（API 36，420dpi）上输入区高度为 79px（即 30sp），光标只有字体自然行高，约 49px，修复前贴在 y 0..48，中心比输入区中线高 15px。占位文字和已输入文字跟同一个装饰层，一起偏上。

处理：只把 `MmField` 装饰层改为垂直居中（`Alignment.CenterStart`）。登录、搜索和添加标签共用这个组件，会一起纠正；没有改编辑器正文、登录校验或接口。版本升至 0.1.17（versionCode 18），以便用同一官方签名覆盖安装 0.1.16。

验证：在 Android 16（API 36）ATD 模拟器上，修复前光标中心为 24px、输入区中线为 39px；修复后光标位于 y 15..63，中心与输入区中线一致。服务器地址和 Token 两个框都通过。Debug 单元测试 47 项运行、0 失败、7 项跳过（仍需要隔离 Memos 服务器）。

残留风险：模拟器通过不等于 Find N6 / ColorOS 通过。ColorOS 字体和显示缩放可能让光标在框内仍有一点偏差；在用户回报之前不能把该机写成已确认修复。

## I30 官方优化包启动即退出

2026-11-09 用户在 Find N6（Android 16 / ColorOS）安装官方签名且开启优化的 0.1.15（versionCode 16）后，应用打开即退出。随后用户安装官方 Actions 侧载 APK，反馈崩溃“又回来了”。曾向用户提供同一 0.1.15、官方签名但关闭优化（`optimization.enable = false`）的诊断包做 A/B：诊断包约 31 MB，正式优化包约 8.6 MB。“又回来了”说明未优化包可以启动，正式优化包再次崩溃。模拟器通过不能代替该机验收；Android 16 ATD 上复现了同一启动崩溃。

对崩溃的正式 APK 做过打包检查：签名校验通过，16KB 对齐看起来正常，`debuggable=false`。

原因：在 Android 16 模拟器上用优化后的 0.1.15 包复现，进程在进入任何 Activity 之前于启动阶段退出，日志为 `java.lang.IllegalAccessError: Class kotlin.text.k extended by class z52 is inaccessible`，发生在 `androidx.startup.InitializationProvider.onCreate`。R8（自 AGP 9.1 起默认开启）把 `kotlin.text.StringsKt__StringNumberConversionsJVMKt` 重打包到未命名包，变成 `z52`，而其包内可见父类仍停留在 `kotlin.text.k`。Android 16 的 ART 在安装 startup provider 时拒绝该子类，进程立即退出。

处理：在 `app/src/main/keepRules/release-startup.keep` 增加 `-dontrepackage`。代码收缩和包内重命名保留，只停止跨包重打包。重建后的优化包仍约 8.2 MB。版本升至 0.1.16（versionCode 17），以便用同一官方签名覆盖安装 0.1.15。未关闭优化，也没有把未优化的大包当作正式包。未更换签名密钥。改动已合并：[Fix optimized release crash on launch](https://github.com/christolan/Memao/pull/3)，合并提交 [34b66ad89ec7d22e1de2faf92286608a58f4eb21](https://github.com/christolan/Memao/commit/34b66ad89ec7d22e1de2faf92286608a58f4eb21)，约 10:16（Asia/Shanghai）。

验证：在 Android 16（API 36）ATD 模拟器上，旧优化包复现上述 IllegalAccessError；0.1.16 冷启动进入登录页（“连接你的 Memos”、服务器和令牌输入框、“连接服务器”），ExoPlayer 完成初始化，崩溃缓冲区为空。Debug 单元测试：47 项运行、0 失败、7 项跳过（需要隔离 Memos 服务器）。

设备反馈：[I31](#i31-登录输入框光标偏上) 记录了用户随后在 Find N6／ColorOS 上成功启动 0.1.16。合并后已启动新的侧载构建：[Actions run 42550061724](https://github.com/christolan/Memao/actions/runs/42550061724)（截至 2026-11-09 约 10:17 Asia/Shanghai 仍在进行）。成功后下载文件应为 [sideload-latest](https://github.com/christolan/Memao/releases/tag/sideload-latest) 上的 `Memao-0.1.16-release.apk`。

## I28 设置页操作辨识、缓存时序与文字测量验收

审查发现并修正：原缓存读取与清理没有明确忙／错状态及请求身份，旧读取可能覆盖后来的清理结果。新增主线程状态控制，启动时同步抢占、读清请求代次、防重复清理、失败保留统计及重试。全账号清理过程中切换账号不取消已开始的操作，完成后采用真实合计统计并抑制旧会话提示。交叉审查进一步发现切账号后 report 为空且清理失败会缺失读取入口，已明确 readError 以开放重读，并加入专项时序测试。

首次测试包编译报错为主 Agent 新增集成测试在协程外调用 suspend selectAccount，已补 runBlocking；产品主包与37项JVM当轮已通过，修正后全部构建成功。ADB首次仪器执行受沙箱本地5037端口限制，按既有I01流程获准连接本机调试服务后正常运行，未绕过审批。

## I27 未修改编辑副本的清理与保存竞态

2026-11-08 用户确认 R70：进入编辑未修改，退出不保存草稿。定位：prepareEdit 原先立即持久保存编辑副本以保护附件，普通退出又调用 saveDraft，导致无内容改动也留下草稿。

实现保留附件保护机制，新增 prepareEditSession 区分本次创建与已有草稿；只清理当前会话有资格处理且最终正文／有序附件与进入基线相同的副本。Repository 在锁内再核验账号、内容、修订号、SAVED 状态、无发送 attempt 和活动发送；只删除符合条件的新增副本，已有草稿与发送过的内容保留。

审查重点及修正：准备过程中在写入前登记新副本，外层捕获取消并用 NonCancellable 清理，覆盖数据库提交后切线程返回前取消；编辑准备互斥区间覆盖取消前任清理与新请求交接，防新请求接走将被清理的副本。退出的保存、条件清理与关闭同处 saveMutex，防后台保存将副本写回。清理 IO 期间若有新输入，循环保存后重判；若开始发送或选附件，递增请求身份取消旧退出路径，保留现场并再次保存。子 Agent 交叉审查未发现阻塞问题。

主包、测试包和 27 项 JVM 构建通过。首轮持久化专项 7 项通过，另一项在完成返回／切页／换账号检查后，被新建空白编辑器的测试断言阻挡：assertTextEquals 同时包含占位提示，实际 EditableText 为空。改为直接核验空 EditableText，产品代码不变，原用例最终复验通过；本轮累计 45 项仪器与 27 项 JVM 共 72 项不同检查通过。0.1.13 初次安装时手机无线调试断开，用户重新打开后连接恢复，保留数据覆盖安装及版本／冷启动核验成功。未改变数据库 schema，不批量清理旧版本已存在的草稿。此轮退出指显式返回、切页或切账号；停留未改动编辑器时强杀／进程回收仍可能保留保护性副本，未增加持久候选标记或启动清理。

## I26 取消笔记详情后的手势、编辑与验收适配

2026-11-08 R69 实施：正文默认 6 行、点击原位展开、长按直接编辑。原 Markdown 的文字选择及原生链接会占用长按，列表专用渲染改为基于实际文字布局计算跨块行预算，并手动区分可见链接短按与长按编辑；普通预览保留原渲染。链接命中检查实际字符框及可见行尾，防点空白或省略号误开隐藏链接。

主 Agent 和子 Agent 审查发现：管理菜单迁至列表后，宽屏可能在编辑中操作笔记，网络返回后若直接关闭编辑会丢失期间输入。实现改为目标草稿先保存，操作完成后保留正在编辑的草稿，后续输入继续自动保存，发送沿用既有冲突规则。
